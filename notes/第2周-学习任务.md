## 2. 五天知识块（每天 1.5–2 小时）

### D1 · HTTP 与第一个 GET（2h）

**要学的**
- URL 的结构：`https://api.open-meteo.com/v1/search?name=北京&count=1`
  - 协议 + 域名 + 路径 `/v1/search` + 查询串 `?key=value&key2=value2`
- `params=` 参数是怎么变成查询串的（requests 会帮你 URL 编码，中文不用手转）
- `requests.get(url, params=..., timeout=...)` 返回一个 `Response` 对象
- `resp.status_code` / `resp.json()` / `resp.text` / `resp.headers`

**要写的 20 行**
```python
import requests

url = "https://geocoding-api.open-meteo.com/v1/search"
resp = requests.get(url, params={"name": "北京", "count": 1, "language": "zh"}, timeout=10)
print(resp.status_code)
print(resp.url)          # ← 看看 params 被拼成了什么样
data = resp.json()
print(data["results"][0]["latitude"], data["results"][0]["longitude"])
```

**验收**
- [ ] 能说出 `resp.url` 里中文变成了什么（URL 编码）
- [ ] 能解释**为什么必须传 `timeout`**（不传时，服务器不响应会一直挂着）

> 硬规则：**任何网络请求都必须带 timeout**。这是本周第一条铁律，没有例外。

### D2 · 状态码（2h）

**必须记住的**

| 码 | 含义 | 你该怎么办 |
|---|---|---|
| 200 | 成功 | 解析 body |
| 301/302 | 重定向 | requests 默认自动跟，不用管 |
| 400 | 参数错 | 是**你的 bug**，检查 params |
| 401/403 | 无权限 / 被拒 | 检查 key、是否被封 |
| 404 | 路径不存在 | 检查 URL 写错没 |
| 429 | 请求太频繁 | **等一会重试**（可重试） |
| 500/502/503 | 服务端挂了 | **稍后重试**（可重试） |

**`raise_for_status()` 是干什么的**
```python
resp = requests.get(url, timeout=10)
resp.raise_for_status()     # 4xx/5xx 时抛 requests.HTTPError，2xx 时什么都不做
```

**要写的 20 行**
- 故意请求一个不存在的路径，打印 `status_code` 和 `resp.text[:200]`
- 再用 `raise_for_status()` 包一层，看异常类型和消息

**验收**
- [ ] 能说清 404 和 500 的区别，以及为什么给用户的提示不一样（"地址错了"vs"对方挂了"）
- [ ] 知道 429/5xx 可以重试，400/404 不要重试

### D3 · 异常层次与 try/except（2h）

**requests 的异常树（记住形状就行）**

```
RequestException                 ← 所有 requests 异常的基类
├── ConnectionError              ← 断网、DNS 失败、连接被拒
├── Timeout                      ← 超时（连接超时 / 读取超时）
│   ├── ConnectTimeout
│   └── ReadTimeout
├── HTTPError                    ← raise_for_status() 抛的
├── TooManyRedirects
└── JSONDecodeError（其实是 json 的，不是 requests 的）
```

**捕获顺序**：子类写在父类前面，否则父类会"抢走"。

```python
try:
    resp = requests.get(url, timeout=10)
    resp.raise_for_status()
    return resp.json()
except requests.Timeout:
    ...          # 超时
except requests.ConnectionError:
    ...          # 断网
except requests.HTTPError as e:
    ...          # 4xx/5xx
```

**要写的 20 行**：一个 `fetch(url, params)`，成功返回 dict，失败返回 `None` 并打印原因。
**先用"返回 None"练**，等 D4 再理解"为什么要自定义异常"。

**验收**
- [ ] 断网时（关 Wi-Fi）得到 `ConnectionError`，程序不崩
- [ ] 能解释为什么不能只写一个 `except Exception:` 了事（会吞掉你自己的 bug）

### D4 · 超时、重试与指数退避（1.5h）

**两种超时**
```python
requests.get(url, timeout=10)             # 总超时（连接 + 读取各 10 秒，粗略理解）
requests.get(url, timeout=(3.05, 10))     # (连接超时, 读取超时) 更精确
```

**什么能重试、什么不能**

| 情况 | 能重试吗 | 为什么 |
|---|---|---|
| `Timeout` | ✅ | 网络抖动，重试常能成功 |
| `ConnectionError` | ✅ | 同上 |
| 429 | ✅ | 但要**退避**（等 2s、4s…） |
| 500/502/503 | ✅ | 服务端临时故障 |
| 400 / 401 / 404 | ❌ | 重试一百次也是同样的错 |

**退避**（指数级，你 `1.py` 里写过一样的）：
```python
import time
for attempt in range(3):
    try:
        ...
        break
    except (requests.Timeout, requests.ConnectionError):
        wait = 2 ** attempt
        print(f"第 {attempt + 1} 次失败，{wait} 秒后重试")
        time.sleep(wait)
```

**验收**
- [ ] 把 `timeout` 设成 `0.001`，能稳定触发超时并看到 3 次重试
- [ ] 能说出"为什么重试要加等待"（不加会被服务器判定为攻击，429 更严重）

### D5 · 从下往上读 traceback（1.5h）

**读法**

```
Traceback (most recent call last):
  File "weather.py", line 42, in main          ← ① 你的代码：第 42 行
    data = fetch(url)
  File "weather.py", line 18, in fetch         ← ② 你的代码：第 18 行（真正出错处）
    resp.raise_for_status()
  File ".../requests/models.py", line 1021     ← ③ 库内部（新手可以跳过）
    raise HTTPError(...)
requests.exceptions.HTTPError: 404 Client Error: Not Found for url: ...   ← ④ 结论
```

**只读 ①②④ 三处**：最后一行告诉你"什么错"，倒数第一个你自己的文件告诉你"哪一行"。中间那一大坨库代码，本周可以先忽略。

**四种最常见的错**

| 最后一行长什么样 | 真实原因 | 怎么查 |
|---|---|---|
| `ModuleNotFoundError: No module named 'requests'` | 没装 / 装到全局去了 | `python -c "import requests; print(requests.__file__)"` 看路径有没有 `.venv` |
| `json.JSONDecodeError: Expecting value...` | 返回的不是 JSON（可能是 HTML 错误页） | 打印 `resp.text[:200]` 看看实际内容 |
| `requests.exceptions.ConnectionError` | 断网、域名错、代理 | 先 `ping` 域名，再验 URL |
| `KeyError: 'results'` | JSON 结构和你以为的不一样 | 先 `print(data)` 再取键 |

**验收**
- [ ] 能看着 traceback 直接说出"哪个文件、第几行、什么原因"
- [ ] 能区分"我的代码的错"和"外部的错"

```

```

### 3.3 错误矩阵（**这才是本周的重点**）

| 场景 | 用户看到的话 | 退出码 |
|---|---|---|
| 城市写错 | `找不到城市「阿斯顿发」，请检查写法（支持中文/英文/拼音）` | 2 |
| 断网 | `连不上网络，请检查 Wi-Fi 或代理设置` | 3 |
| 超时 | `请求超时（10 秒），请稍后重试` | 3 |
| 服务端 5xx | `天气服务暂时不可用（HTTP 503），请稍后再试` | 4 |
| 被限流 429 | `请求太频繁，请等一会儿再试` | 4 |
| 返回不是 JSON | `服务返回了无法解析的内容（可能被网络拦截）` | 4 |
| 参数错误（400/401） | `请求参数有问题（HTTP 400），这是程序 bug` | 5 |
| 正常 | 一行天气 | 0 |

> **每一个退出码都要能在 PowerShell 里用 `echo $LASTEXITCODE` 看到。** 这是"程序可控"的硬证据。

### 3.4 建议的结构（沿用上周的分层思路）

```

get_weather(lat, lon, unit)        → 经纬度 → 天气 dict
format_weather(data)               → dict → 一行文本

```

**不要**写成一个大函数从上撸到底 —— 上周 `todo.py` 的分层你已经体会过一次了。

## 6. 八个必踩的坑

1. **忘写 `timeout`** → 程序永久挂起，你以为死机了。
2. **`resp.json()` 不判断内容** → 服务器返回 HTML 错误页时抛 `JSONDecodeError`，用户看到一堆红字。
3. **中文城市名手拼 URL** → 必须用 `params=`，否则编码错误。
4. **`except Exception` 一把抓** → 连自己的拼写错误也吞掉，调试时找不到原因。
5. **重试不退避** → 触发 429，越试越糟。
6. **捕获顺序写反**（`RequestException` 写在 `Timeout` 前面）→ 永远进不了 Timeout 分支。
7. **把 traceback 直接打给用户** → 用户看不懂，等于没处理。
8. **依赖没装就开写** → 写了两小时，最后 `ModuleNotFoundError`。
